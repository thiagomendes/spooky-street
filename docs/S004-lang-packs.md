- **Decision 3, GitHub Pages (a).** `catalogUrl` is `https://thiagomendes.github.io/spooky-street/packs/catalog.json`,

  PlayMode test that runs the real `UnityWebRequest` downloader against a loopback `HttpListener`.

## 1. What was built

### Pack format (Core, engine-free)

- **`StringTable` schema 2.** It is the current JSON. An entry may have `"plural": { "one": …, "other": … }` in place of
  `"value"`, and `other` is required. Schema 1 files still load. `ToJson()` writes either schema. `en.json` is now
  schema 2. `ui.title.recap_stickers` ("{0} sticker/stickers") and `ui.title.continue_detail` (by the bat count) are
  plural, and the recap view uses `LocalizedText.SetPlural`.
- **`PluralRules`.** CLDR whole-number rules for en, de, nl, pt (0 and 1 are "one", whole millions are "many"), fr,
  es and it. Other languages get "other" for every count. "many" may fall back to "other".
  `LocalizationCatalog.Plural(key, count, args)` picks the form with the rules of the table that has the key (the
  active pack, else English).
- **`PackManifest` / `PackCatalog`.** Each manifest has locale, nativeName, contentVersion, tableSchema, size, sha256,
  file (relative to the catalog) and an optional `development` flag. The catalog is
  `{ "catalogVersion": 1, "packs": [...] }`. A newer catalog version is refused. A bad entry is skipped.
  Locales must be letters, digits and hyphens, so they are safe as file names.
- **`PackValidator`.** Runs before a pack is switched on. It checks, in order:
  1. size (short → `Interrupted`, long → `TooLarge`);
  2. SHA-256 (`HashMismatch`);
  3. strict UTF-8 with no BOM;
  4. table schema, from both the manifest and the file (`NewerSchema`);
  5. that the locale matches the manifest;
  6. per key: `{n}` placeholders (the general form keeps English's set, may reorder, and a "one" form may drop the
     count), rich-text tags, and that `string.Format` accepts the text;
  7. plural forms: plural exactly where English is plural, and every form the locale requires;
  8. **font coverage** of every character, the native name included, against `FontCoverage`;
  9. key coverage of at least 80 % of English. Missing keys show English. Keys English does not have are ignored.
- **`FontCoverage.cs`** is generated by `tools/l10n/l10n.py coverage` from the intersection of Andika Regular,
  Andika Bold and Sniglet ExtraBold. That is Latin-1 plus a few letters, because Sniglet has only 241 glyphs. It
  covers pt-BR, es, fr and de. It rejects Cyrillic, CJK and emoji.
- **The pseudo-language now uses only glyphs that all three fonts draw.** The old pseudo letters (ƀ đ ğ ŵ …) were
  missing from Sniglet, so titles fell back to the OS font. The new map is `ábçðéƒ…ÅÇÐÉ…`, and its name is `[Þšéüðö]`.
  It is still +35 % with brackets, and placeholders are kept.

### Install pipeline (`PackInstaller`, over `ISaveFileSystem`)

1. Validate the downloaded bytes.
2. Optionally check free space (3× the size).
3. Write `languages/<locale>.staging`, read it back and check its hash.
4. Move it to `languages/<locale>-<sha16>.json`. A reinstall keeps a good copy and replaces a damaged one.
5. Switch the index `languages/installed.json`. It is written like a save: temp file, atomic replace, one
   `.prev.json` copy.
6. Only then delete the locale's old file.

At launch `Load()` re-reads the index and re-validates every pack, offline. A missing or damaged pack is left out
and never half-loaded. Any IO error leaves the old index and files in place, and the staging file is removed.

### Orchestration (`LanguagePacks`, `LanguageChoice`, `LanguageConfig`)

- **Options, in order:** English, then built-in slots whose table ships, then installed packs, then catalog packs
  (only after the catalog was fetched). Development packs are hidden in production builds, both in the catalog and
  when already installed.
- **Network calls.** There are none at launch. `FetchCatalog` and `Download` are the only ones, and both are called
  only behind the gate. Downloads run one at a time, with progress. URLs must be HTTPS, and pack files must be on
  the catalog's own host (loopback HTTP is allowed only by a test flag).
- **Launch language.** A language the player chose is kept while it is usable, else English. Before any choice, the
  device language picks a matching usable pack: exact tag first, then the same language ("pt-PT" finds "pt-BR").
  The pseudo-language is never picked from the device. The new `PreferencesData.LocaleChosen` field (schema
  unchanged, defaults to false) records whether the player has chosen. Language lives only in preferences, never in
  case progress.

### Runtime

- **`PackDownloader`.** `IPackTransport` over UnityWebRequest: one plain GET with no custom headers, a 30 s timeout,
  at most 2 redirects and a size cap. It runs on unscaled frames.
- **`LanguageController`.** Created at boot by `GameBootstrap.CreateLanguages`. It loads the config and the
  installed packs, picks the launch language and switches `Localizer.Catalog`. `Use`, `Download` and `Remove` live
  here. Removing the active pack reverts the game to English. The choice is saved through
  `GameAudio.SetPreferences`. For tests it has `TransportOverride`, `CatalogUrlOverride`, `AllowLoopbackHttp` and
  `DeviceLocalesOverride`.
- **`LanguageScreen`.** Its own canvas at sorting order 14, under the parent gate's 16.
  - **Opened from:** the title's globe pill, which replaces the dev pseudo toggle and is shown in every build, and a
    new globe disc on the pause card (top-left; the settings gear is top-right).
  - **Rows:** at most 4. Each shows the native name and a note: "In the game", "Downloaded · 58 KB", "58 KB",
    "Downloading 40%" with a bar, or "That did not work. Nothing changed.".
  - **Actions:** Use (no gate), or an "In use" tag. Download or Update and Remove appear only after the gate. Every
    Remove asks for the gate again. "More languages" opens the gate, then fetches the catalog. The status line shows
    checking, none or offline.
  - **F1 hook:** `FocusOrder`, `DefaultFocus`, `Back()` and `Opened`/`Closed`. Buttons already have explicit
    wrap-around up/down navigation, so a gamepad works today, and focus survives the rebuilds that download progress
    causes. F1 (`UiFocusGraph`, `UiFocusScreen`) merged to `main` (b097e6b) while this branch was in CI. The branch
    merges with it cleanly but is not wired to it yet. The follow-up is to build a `UiFocusGraph("languages")` with
    one row per language row (Use/Download, Remove), then "more" and "close" (`Exit = "close"`), and attach it with
    `UiFocusScreen.Attach(Canvas.transform, graph, overlay)`. Bind the buttons by id, set `BackOverride` to null so
    Back runs Close, re-bind after each `Rebuild`, and validate every state (English only, unlocked with a download
    in progress, installed) in a Core test.
- **Strings.** 15 `ui.language.*` keys with translator context in one block of `en.json`, through
  `LocalizationKeys.Languages`. The pill's context no longer says "development only". Language names come from each
  table's `nativeName` and are never translated.

### Tools and CI

- `tools/l10n/l10n.py` has three commands:
  - `coverage` regenerates `FontCoverage.cs`;
  - `packs --out build/packs` writes `qps-ploc.json` and a `catalog.json` with size and sha256, ready for a Pages
    workflow;
  - `check` confirms `FontCoverage.cs` is current and runs the font, placeholder, tag and plural checks on every
    bundled table, on the pseudo pack and on `languages.json` (HTTPS URL, drawable slot names).
- `check` runs in `check-local.sh` and in the CI static job. `fonttools==4.68.0` was added to
  `tools/requirements-ci.txt`. `validate_project.py` now accepts `en.json` schema 1 or 2.

    - a full disk keeps the old pack and removes the staging file;

## 4. How D2 adds pt-BR

1. Write `Assets/SpookyStreet/Content/Resources/Localization/pt-BR.json`:
   - copy of `en.json` with `"locale": "pt-BR"` and `"nativeName": "Português (Brasil)"`, same keys and contexts,
     and schema 2;
   - plural entries need `one` and `other` (pt: 0 and 1 are "one");
   - then run `python3 tools/unity_meta.py` for its meta.
2. Nothing else is needed to ship it. The existing built-in slot in `languages.json` picks it up. Brazilian devices
   (`SystemLanguage.Portuguese` → "pt-BR") start in it until the player chooses, and it shows on the language
   screen as "In the game".
3. Add the D2 checks:
   - a Core test that `pt-BR.json` passes `PackValidator.ValidateText` (build a manifest with
     `PackManifest.For(table, "pt-BR.json")`, or call `ValidateText` directly) with **100 % coverage**;
   - each value within +35 % of English;
   - the fear-word and conclusion lint in pt-BR.

   `l10n.py check` already runs the glyph, placeholder, tag and plural checks on every table in that folder.
4. For option (b), remove the slot from `languages.json`, run `l10n.py packs`, and add pt-BR to the published
   catalog.

## 5. Gaps and notes

- **No real host yet.** Pages is not enabled, and no workflow publishes `build/packs`; that is left for the owner's
  decision 3. Production builds already show the globe, and "More languages" reports offline until the host exists.
- **Device language.** Unity's `Application.systemLanguage` gives one language with no region or preference list.
  "Portuguese" maps to pt-BR and "Spanish" to es-419. Reading the full iOS preferred-languages list needs a native
  plugin (later, behind an interface).
- **Rows.** At most 4 rows are shown (English, pt-BR, pseudo plus one). More languages will need a scrolling list.
- **Orphaned files.** A crash between switching the index and deleting the old file can leave one orphaned old pack
  file. It is harmless: the index no longer lists it.
- **No glyphs on the Remove/Download icons.** They reuse `icon_close`, `icon_arrow` and `icon_check`. No new art.
